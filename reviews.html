ℹ️ Основные изменения

0.1Что не так с текущей версией

Ниже — разбор реализации, которую выкатили как «готовую». Сравнивайте с прототипом.

Макет «Мессенджера» вместо списка и карточки

В текущей версии используется двухколоночный макет: слева список, справа детали. Для потока отзывов это неудобно: менеджеру нужно быстро сканировать текст, а половину экрана занимает пустая панель. В новой версии — компактный список по центру и выезжающая карточка (drawer) по клику.

Почему это критично: менеджер должен окинуть взглядом 10–15 отзывов, а не читать один в пол-экрана.

Перегрузка статусами в шапке

В текущей версии 8 табов: «Все, На проверке, Нужен менеджер, К отправке, Ошибки, В работе ИИ, Отвечены менеджером, Ответ не нужен». Это перегружает интерфейс. Мы оставляем 3 понятных состояния: На проверке, Нужен менеджер, Отвечено (в виде выпадающего списка).

Нет редактирования и шаблонов

Нельзя отредактировать отправленный ответ и нельзя использовать заготовки. Мы добавляем функцию редактирования (с учетом лимитов WB) и кнопку «📋 Шаблоны».

Итого: текущая версия — это «просмотр отзыва». Новая — «конвейер по обработке потока».

1Принципы работы

  • AI уже предложил ответ — он лежит в поле. Менеджер либо соглашается, либо меняет. Никогда не пишет с нуля.
  • Менеджер идёт потоком — клик по строке → drawer → одобрить → автопереход к следующему.
  • Всё на одном экране — мини-дашборд товара, медиа покупателя, AI-ответ и кнопка одобрения.

2Четыре кнопки в шапке ответа

  • ❓ Что не так с ответом? — открывает поповер с уверенностью AI, категорией и чипами причин. Уходит в дообучение промптов. Ответ не меняется.
  • ✦ Перегенерировать — циклично меняет варианты (нейтральный → короткий → мягкий).
  • ✎ С указанием — открывает поле для своего промпта к AI.
  • 📋 Шаблоны — выпадающее окно с готовыми ответами (поиск, редактирование, добавление, сохранение в localStorage).

3Редактирование отправленных ответов

Ограничения WB API: Редактирование возможно через PATCH /api/v1/feedbacks/answer. Важно: изменить текст можно только 1 раз и только в течение 60 дней с момента первой публикации.

Как это в UI: после отправки показываем плашку «Ответ отправлен» с кнопкой «✎ Редактировать». Если ответ уже был отредактирован (или прошло 60 дней) — кнопка исчезает, а под текстом появляется приписка «Был изменён 1 раз» или «Срок истёк».

4Кнопка «↩» (Инициировать возврат)

Показывается в шапке карточки, если статус заказа — ВЫКУП. При клике открывается мини-поповер внизу: «Инициировать возврат? [Да] [Нет]».

5Медиа покупателя (Лайтбокс)

Фото покупателя показываются миниатюрами. При клике открывается полноэкранный лайтбокс (как в «Возвратах»), а не новая вкладка.

6Картинка товара — алгоритм генерации

Временное решение. Когда появится БД товаров — ссылки будут храниться в записи товара. Сейчас генерируем по NM на лету.

Шаг 1. Вычисляем vol и part

vol  = Math.floor(NM / 100000)
part = Math.floor(NM / 1000)

Если vol > 3269 — ФОРМУЛА С mns-basket-cdn НЕ РАБОТАЕТ. Проверено на живых данных (vol=11796 живет на basket-43, а не на mns-08). Поэтому сразу переходим к перебору.

Шаг 3. Перебор (fallback)

Если картинка не загрузилась (ошибка onerror), запускаем перебор:

  • Для vol > 3269: идем с конца basket-50 → basket-01.
  • Для остальных случаев: basket-01 → basket-50.
  • Затем: mns-basket-cdn-20 → mns-basket-cdn-01.
  • Для каждого хоста проверяем размеры: big → c516x688 → c246x328.
  • Первые 6 URL проверяем последовательно, остальные батчами по 9 параллельно.

Рабочий URL кэшируется в памяти до перезагрузки страницы.

Шаг 4. Размеры

big — основной. c516x688 — если big нет. c246x328 — последний резерв. Размера orig у WB по ссылкам нет.

7Пометки на будущее

📌 На будущее: сейчас кнопка «✎ С указанием» открывает поле для промпта. В будущем — добавить шаблоны быстрых указаний для AI (например, добавь больше эмпатии), чтобы ускорить работу менеджеров.
