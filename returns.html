ℹ️ Основные изменения

0.1Что не так с текущей версией

Ниже — разбор текущей реализации интерфейса. Это не просто редизайн ради красоты, а перестройка логики под реальную работу менеджера потоком. Сравнивайте с прототипом.

Карточки-аккордеоны вместо таблицы

В текущей версии каждый возврат — большая карточка, на экран влезает 3–4. Чтобы понять «что горит сегодня», менеджер листает страницы и раскрывает карточки по одной. В новой версии — таблица: 15–20 заявок видны сразу, дедлайн и причина в каждой строке. Можно глазами найти «⏳ истёк» и «⏳ 2 ч.», не открывая ничего.

Почему это критично: такой интерфейс позволяет показать всё, что надо решить сегодня, отсортировать по срочности и быстро разобрать потоком.

Нет дедлайна — есть только «дата создания»

На карточке видно время создания («17 окт., 14:03»), но сколько осталось до автодобрения — неизвестно. Менеджер вынужден держать лимиты в голове. В новой версии добавляем бейдж ⏳ 2 ч. / ⏳ 1 дн. / ⏳ истёк прямо в строке таблицы и в карточке, с цветовой шкалой (серый / оранжевый / красный).

Техническая сложность: в API возвратов поля «дедлайн» нет — только dt (дата создания). Дедлайн считаем сами: deadline = dt + PLATFORM_DEADLINE[marketplace] * 24ч.

Нет автоперехода

Текущий сценарий: «Принять решение» → модалка → подтвердил → закрылась → надо вернуться в список, найти, где остановился, скроллить, открыть следующую. Это 5+ действий на каждую заявку. В новой версии добавляем тумблер «Автопереход» в топбаре. После подтверждения drawer сам открывает следующую неразобранную заявку. В потоке из 36 заявок это сотни сэкономленных кликов в день.

Статусы не соответствуют бизнес-логике

Сейчас три статуса: UNDER_REVIEW / APPROVED / REJECTED. Вводим четыре статуса, добавляя «Уточняем».

  • Ждёт решения — новая, не читали.
  • Уточняем — менеджер задал вопрос покупателю в чате, ждёт ответа. Это не «ждёт решения» (площадка ещё не получила ответ), но и не финал — к заявке нужно вернуться позже.
  • Одобрено / Отклонено — финал.

Без этого статуса такие заявки висят в общем потоке и путаются с новыми.

Нет цветового кодирования маркетплейсов

Сейчас маркетплейс определяется только по маленькому логотипу. Логотипы WB/ЯМ/OZ похожи по форме, при быстром взгляде их сложно различить на автомате. В новой версии: цветная полоса слева на строке (WB — фиолет, ЯМ — жёлтый, OZ — синий) + пилюля WB / YM / OZ рядом с артикулом + чип в карточке. Менеджер видит распределение по площадкам боковым зрением.

Смешанные валюты в одной колонке

В карточках встречаем «451 ₽», «16 716 ₽», «47 Br» и просто числа без валюты («2 700 051»). Непонятно, что означает каждая цифра. Лучше просто убрать цену за товар.

Фильтр «Кабинет» вместо «Площадка»

«Кабинет» — это внутренний WB-кабинет. Для ЯМ и Ozon это понятие не работает. Делаем универсальный фильтр «Площадка» (WB / ЯМ / Ozon). Плюс расширяем набор фильтров: Статус, Бренд, Причина, Площадка, Период, Сортировка + кнопка «Сбросить».

Нет фильтра «Причина» — ключевого для триажа

Менеджеру часто нужно разбирать партиями: «покажи все браки, я посмотрю скопом» или «покажи всё, что связано с несовпадением комплектации». Этого нет. Добавляем фильтр «Причина» (Брак / Не то / Не подошёл / Передумал).

Нет сводки по фильтру

Сейчас показывается просто «578 заявок» — непонятно, сколько из них ждут, сколько горит сегодня. Выводим строку «Ждут решения N · Истекает сегодня N · Решено N». Менеджер сразу понимает объём работы.

Нет быстрых действий

Сейчас одна кнопка «Принять решение», которая открывает модалку с 6 опциями. Мы добавляем три быстрые кнопки прямо в карточке (🚫 брак не обнаружен / 📷 нужно больше фото / ✅ одобрить и забрать). Плюс полное меню для специфичных случаев (🎁 одобрить без возврата / 🔧 сервисный центр / 💬 свой комментарий). На частых кейсах менеджер не открывает меню вообще.

Нет шаблонов для отказа

При отказе со своим комментарием менеджер каждый раз пишет текст с нуля. Добавляем библиотеку шаблонов с редактированием через карандашик и сохранением в localStorage + кнопка «+ Новый шаблон». Плюс второй шаг подтверждения: менеджер видит, что именно уйдёт покупателю, и может вернуться к редактированию.

Нет внутренних заметок

Если менеджер узнал у поставщика «партия бракованная» — он никак не фиксирует это в интерфейсе. Знание теряется, следующий менеджер начинает с нуля. Добавляем иконку 🔒 в строке (если есть заметка) + превью в drawer'е + модалка редактирования. Заметка видна только команде.

Нет аналитики по товару

Если у товара 5+ возвратов за 30 дней — это сигнал о проблемной партии. Сейчас менеджер смотрит на одну заявку и не видит паттерн. Добавляем иконку ⚠️ при превышении порога в колонке действий + кликабельный чип «📊 N возвратов за 30 дней» в карточке. Клик открывает модалку с KPI (Всего / Ждут / Одобрено / Отклонено) и разбивкой по причинам.

«Чат по этому заказу — покупатель не писал»

Сейчас это мёртвая информация: чата нет, но и начать его нельзя (в API нет createChat). Заменяем на пустой state в карточке: «💬 Чат с покупателем не открыт» одной строкой, без отдельного громоздкого блока. Если покупатель напишет — чат появится с полем ввода.

Поиск не игнорирует фильтры

Если включён фильтр «Одобрены», и менеджер ищет артикул «R125-001», он найдёт только одобренные. Отклонённую не найдёт, хотя ищет вещь, а не статус. Меняем логику: при вводе в поиск фильтры отключаются, поиск идёт по всей базе. Менеджер ищет артикул, а не «артикул в подмножестве».

Итого: текущая версия — это «показать заявку». Новая — «обработать поток». Это разные задачи, и UI у них разный.

1Заявка = запрос на возврат

Покупатель указал причину, комментарий и фото. Менеджер принимает решение. Всё, что нужно для решения, лежит на одном экране — не надо ходить в личный кабинет площадки.

2Дедлайн на решение

Если не вынести решение в срок — заявка одобряется автоматически. Дедлайн считаем сами: берём дату создания заявки (dt) и прибавляем лимит площадки. В API возвратов поля «дедлайн» нет, только дата создания.

3Варианты решения

Клик на «Выбрать решение» → модалка с 6 опциями → шаг подтверждения в той же модалке. После подтверждения футер показывает статус без кнопок — заявка решена. Никаких «сохранить на завтра».

  • ✅ Одобрить и забрать товар — деньги после получения товара на складе.
  • 🎁 Одобрить без возврата — товар остаётся у покупателя.
  • 🚫 Отклонить: брак не обнаружен
  • 📷 Отклонить: нужно больше фото и видео
  • 🔧 Отклонить: обратиться в сервисный центр
  • 💬 Отклонить со своим комментарием

4Чат с покупателем

Если по заказу уже есть чат — показываем переписку и поле ввода. Если чата нет — пишем, что диалог ещё не открыт.

5Последние отзывы по товару

Под чатом показываем последние 5 отзывов по этому товару с оценкой 3★ и ниже. Это контекст: если по товару уже есть негатив — возможно, покупатель писал его же. Если отзывов 3★ и ниже нет — показываем, что их нет, это тоже сигнал.

Почему нельзя показать «отзыв именно по этому заказу»: в API отзывов нет orderId. Есть только nmId (товар), lastOrderShkId (штрихкод) и lastOrderCreatedAt (дата последнего заказа). Прямой связи «возврат → отзыв» нет. Поэтому — последние отзывы по товару.
Полезное в отзывах: поле orderStatus (buyout / returned) — готовый сигнал. isAbleReturnProductOrders — можно ли запросить возврат прямо из отзыва. returnProductOrdersDate — дата возврата, если был.

6Внутренние заметки

🔒 — заметка видна только команде. Если есть — превью под товаром, полный текст и редактирование — по клику в модалке. Небольшой значок 🔒 в строке таблицы, чтобы было видно, что заметка есть. Без этого знание теряется: следующий менеджер начнёт с нуля.

Зачем: менеджер узнал у поставщика, что партия бракованная — надо записать. Без этого знание теряется: следующий менеджер начнёт с нуля. В текущей версии заметок нет — и это боль.
📌 На будущее: если заметку кто-то отредактировал (updatedAt > createdAt), показывать маленький бейдж «!» — чтобы привлекать внимание команды к «свежей» правке. Не «есть заметка» (это уже видно по 🔒), а «заметка изменилась, посмотри». В текущей версии бейджа нет — чтобы не создавать лишний визуальный шум.

7Аналитика по товару

Если у товара 5+ возвратов за 30 дней — в колонке действий появляется ⚠️ с числом, а в drawer'е — кликабельный чип «📊 N возвратов за 30 дней». Клик → модалка с KPI (Всего / Ждут / Одобрено / Отклонено), разбивкой по причинам полосками и списком заявок.

Зачем: менеджер смотрит на один возврат и не видит паттерн. Если по этому же товару было ещё 5 возвратов с причиной «брак» — это сигнал, что партия проблемная. Без аналитики — не заметит.
📌 На будущее: аналитика задумана как единая панель по товару — возвраты, отзывы, вопросы и чаты в одном месте. Сейчас в макете только возвраты. Для отзывов и вопросов связка по nmId точно есть. Для чатов — через nmID в goodCard. Для заказов — по srid из отчётов о продажах.

8Маркетплейсы — цветовое кодирование

Строки таблицы подсвечиваются цветной полосой слева в зависимости от площадки. Это позволяет менеджеру мгновенно видеть поток по маркетплейсам, не отвлекаясь на чтение текста.

Wildberries Яндекс Маркет Ozon

Тот же цвет используется в пилюле маркетплейса рядом с артикулом и в чипе площадки в карточке возврата.

9Фоновый прогрев картинок

Менеджер работает потоком и переключается между разделами. Ждать загрузки картинок при каждом переходе — это секунды простоя. Поэтому картинки грузятся заранее, в фоне.

  • Как только зашли на сайт — стартует прогрев картинок из всех разделов: фото товаров, фото покупателей из заявок на возврат, аватарки чатов, превью отзывов. Пока читаете первый раздел — остальное уже качается.
  • Прогрев идёт тихо — без спиннеров и индикаторов. Через new Image() в фоне — браузер сам кладёт их в кеш.
  • Не блокирует интерфейс. Если сразу кликнули в «Возвраты», картинки могут грузиться на месте как обычно.
  • Только фото. Видео (mp4, 5–30 MB) не прогреваем — в плитке медиа показываем плашку «🎬 Видео», сам файл грузится только при клике в лайтбоксе.
  • Два размера. Маленькие превью (для плиток и drawer'а) прогреваем первыми, крупные — только при открытии лайтбокса.
  • Кеш. Браузерный кеш + Cache-Control на стороне CDN — повторные заходы и переключения между разделами берут из кеша.
Что это даёт: зашли на сайт → 30–60 секунд работаете в «Отзывах» → переключились в «Возвраты» — фото покупателей уже на месте, без мигания и ожидания. Ощущение, что сайт «лёгкий», хотя за кулисами уже скачано несколько сотен картинок.
